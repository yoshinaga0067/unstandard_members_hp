# Glossary Quick Reference

A plain-language explanation of terms that come up frequently in projects.

| Term | What it means | Think of it as… |
|------|--------------|-----------------|
| Repository | A folder that holds every file in the project | A binder containing all blueprints for a property |
| Branch | A safe working copy so changes don't affect the live version | A photocopy of blueprints to try out a floor-plan change |
| develop | The working branch — all changes go here | The working copy you mark up before it's approved |
| main | The production branch — what's actually live | The official, client-ready set of blueprints |
| Commit | Saving a snapshot of your changes with a short note | Stamping a design revision with a date and description |
| Push | Uploading your commits to GitHub | Sending updated blueprints to the central file room |
| Pull Request (PR) | A request for someone to review and approve your changes | Submitting a design change for sign-off by a manager |
| Merge | Applying approved changes into main | Updating the official blueprints with the approved revision |
| Deploy | Publishing the website to the internet | Handing over a completed home to the client |
| Build | Converting code into a working website | Constructing the house from the approved blueprints |
| Environment variable | A secure place to store secrets like API keys and passwords | A locked key box that only authorised people can open |
