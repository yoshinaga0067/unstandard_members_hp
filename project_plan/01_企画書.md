# 1. エグゼクティブサマリー

本企画は、UNSTANDARDの全国加盟店（工務店）に提供する新しいWebプラットフォームの構想である。既存の加盟店サイト（本部が商品・施工事例を一括配信し、加盟店が地域情報を載せる仕組み）の良さを引き継ぎつつ、不足している「リードの獲得から成約までの導線」「購入の意思決定支援」「広告ROI・成果の可視化」を、加盟店ごとにON/OFFできるモジュール型のオプションとして拡張する。

ねらいは明快に二つ。すなわち、加盟店の「受注を増やす」ことと、「手間を減らす」ことである。本書では、機能の優先度（影響度×実装負荷）を整理したうえで、『これは本当に全国の工務店が喜ぶサービスになるのか』を批判的に再検証し、必要な改善を加えた。結論として、機能を並べるだけでは不十分であり、(1)成果（受注）への直結、(2)現場の手間の最小化、(3)ソフトウェアに加えた本部の伴走支援、(4)リード所有権を含むデータ信頼、の4条件を満たして初めて、加盟店から強く支持されるサービスになる。

加えて、多数の加盟店の見込み客（個人情報）を1つの基盤で預かるため、セキュリティとプライバシーを最重要事項として見直した。とりわけ、テナント間のデータ分離、個人情報保護法（APPI）対応、本部の強い権限の統制（監査とリード所有権）を、設計の前提として組み込む。

# 2. 背景：UNSTANDARDと既存加盟店サイトの現状

UNSTANDARDは「これまでのスタンダードとは違う価値」を掲げる住宅ブランドで、規格住宅（WOODBOX／NONDESIGN／各種コラボ商品）を、全国の加盟工務店がフランチャイズとして取り扱う。本部はブランド・商品・販促・メディアを提供し、地域の加盟店が建築・販売を担う。

既存の加盟店サイトは、各加盟店が自前でWebを構築せずにサブサイトを持てる仕組みで、本部が商品ラインナップや施工事例（本部事例）を一括配信し、加盟店は完成見学会・相談会の告知や自社の施工事例・お客様の声を掲載できる。全国の加盟店マップや成功事例の共有コミュニティ、研修・集客セミナーも提供されている。

つまり、本企画が土台とする「本部が共通コンテンツを配信し、加盟店が地域コンテンツを編集する」マルチテナント構造は、すでに実運用で価値が証明されている。

# 3. 課題と機会（伸びしろ）

一方で、現状は「見せる（カタログ的な）」サイトに寄っており、次の領域に明確な伸びしろがある。

- リードを「獲得 → 管理 → 成約」までつなぐ仕組みが手薄（来場予約・問い合わせの取りこぼし）。

- 価格・資金・予約・診断など、購入の意思決定を後押しする道具が不足。

- 広告ROIや成果（来場〜成約）の可視化が見当たらず、加盟店が販促の費用対効果を判断できない。

- スマホ更新・LINEなど、多忙な現場が使いやすい運用ツールに余地がある。

これらは、加盟店の受注に直結する領域であり、本企画の機会である。

# 4. 本企画の目的とビジョン

**北極星指標（最上位の目的）：**加盟店の「受注」を増やし、「手間」を減らす。

すべての機能・施策は、この二つのどちらか（できれば両方）に貢献することを採用基準とする。ダッシュボードや管理画面そのものが目的ではなく、来場予約・資料請求・相談・成約という成果に効くかどうかで価値を測る。

ブランド面では「LIFE IS COLORFUL／“好き”で暮らしをデザインする」という世界観を、全加盟店サイトで一貫して体現する。地域の裁量（価格・在庫・イベント・事例）は尊重しつつ、ブランドは本部が統一管理する。

# 5.「全国の工務店が本当に喜ぶか」の再分析と改善

## 5.1 工務店のリアル（前提の検証）

全国の加盟店の多くは、専任のマーケティング担当を持たない小〜中規模の工務店であり、経営者・スタッフは現場対応で多忙、デジタルツールに不慣れな場合も少なくない。彼らが本当に評価するのは「機能の多さ」ではなく、「結果（受注）が出ること」と「自分たちの手間が増えないこと」である。この前提を外すと、どれだけ高機能でも使われず、喜ばれない。

## 5.2 喜ばれるための設計原則（5原則）

- 結果で語る：すべての機能を受注（来場・相談・成約）への貢献で説明し、ダッシュボードは「次の一手」を示すところまで踏み込む。

- 手間を最小化：本部が初期設定とコンテンツの大半を用意し、加盟店は地域情報を少し足すだけで完成。スマホからの更新を前提にする。

- シンプル第一：機能はオプション化し、各店は必要なものだけON。管理画面は自店に自動スコープし、専門用語を避けやさしい日本語と例示で補助する。

- ソフトウェア＋伴走支援：素材提供・初期設定代行・広告運用サポート・研修・成功事例コミュニティを“セットで”提供する（5.3）。

- データ信頼：加盟店の見込み客は加盟店のもの。本部が見るのは集計・ベンチマークであることを明示する（5.4）。

## 5.3 提供形態：ソフトウェア＋本部の伴走支援

小規模工務店にとって、ツールを渡されても自走できないことが最大の離脱要因になる。よって本企画は「ソフトウェア単体」ではなく「本部の伴走支援込みのパッケージ」として提供する。具体的には、ブランド準拠の販促素材（チラシ・SNS・広告クリエイティブ）の配布、初期サイト設定の代行、広告運用の支援メニュー、定期研修と全国の成功事例共有である。これにより、マーケ人材のいない店でもプロ品質の集客が回り、はじめて“喜ばれる”水準になる。

## 5.4 データ信頼とリード所有権（重要）

本部が全加盟店の価格や成果を横断で見られる設計は、運用効率と販促支援に有効だが、加盟店から見ると「監視されている」「顧客を取られるのでは」という不信につながりかねない。これはフランチャイズの信頼問題であり、設計で先回りして解消する。

- 見込み客（個人情報）は加盟店に帰属する。本部は原則として集計・ベンチマーク（件数・CVR・CPA等）を見るのであって、他店の顧客を引き抜くために個別情報を使わない。

- 本部が閲覧できる範囲を明示し、個別の個人情報へのアクセスは制限・監査ログ対象とする。

- ベンチマーク参加は価値提供として設計し、透明性を担保する。

この方針を明確にすることで、横断可視化は「監視」ではなく「本部による販促支援」という価値に転換できる。

## 5.5 公平な課金と既存ツールとの統合

価格感度の高い加盟店に対し、オプションを過剰に細切れ課金すると不信を招く。コア機能は無料（フランチャイズ標準提供）とし、付加価値オプションはROIで説明できる明快な料金体系にする。また、SUUMO等のポータル、LINE、各店が既に使う広告代理店などを“置き換える”のではなく“統合・共存”する姿勢を取り、導入のハードルと反発を下げる。

## 5.6 結論（本当に喜ぶか）

**条件付きでYes。**機能を並べるだけでは喜ばれない。5.2の5原則—とりわけ『結果に直結』『手間最小』『伴走支援』『データ信頼』—を満たす設計・運用にすることで、全国の工務店が継続的に支持するサービスになる。本書の以降の章とロードマップは、この条件を満たす前提で構成している。

# 6. システム全体像（マルチテナント＋モジュール型）

基盤は、フランチャイズ向けのマルチテナントCMS（テナント＝加盟店、運営＝本部）。本部が商品・ブランドメディアを共有配信し、加盟店は地域コンテンツを編集する。表示はパス型（例：サービス名.com/＜加盟店＞）で、デザインはブランド準拠の範囲でテーマを切替える。

機能は「コア＋オプション（モジュール）」で構成する。コアは最小限に保ち、各オプションは決められた拡張ポイントに接続する“疎結合の部品”として実装する。加盟店ごとにON/OFFでき、プランや課金状態に応じて段階提供できる。これにより、2つ目以降の機能追加は本体を改修せず“載せるだけ”になり、将来の拡張に強い。

# 7. 機能と優先度（影響度 × 実装負荷）

機能は影響度（受注貢献・横展開価値）と実装負荷で4象限に整理した。要約は次の通り。

| **区分** | **機能** | **ねらい** |
| --- | --- | --- |
| ★ 最優先 | 施工事例の強化＋絞り込み／販促素材ライブラリ／“好き”診断／資料請求デジタル化 | 軽い負荷で早期に体験を底上げ、リード獲得 |
| ◆ 戦略投資 | 来場予約＋簡易CRM（核）／価格・資金シミュレーター／広告ROI分析（Meta連携）／LINE連携／成果可視化＋全国ベンチマーク | リード獲得とROIを本格化 |
| ○ 余裕で対応 | ローカルSEO・GBP連携／スマホ現場更新＋SNS | 低負荷で地域集客を底上げ |
| △ 後回し | オンライン内覧（360°）／AIチャット相談／オーナーコミュニティ＋紹介 | 効果はあるが負荷大、後段で |

**まず始める4つ（推奨）：**施工事例の強化／販促素材ライブラリ／“好き”診断／来場予約＋簡易CRM。いずれも負荷が軽い、または核となり、両方の価値（喜ぶ・販売貢献）に効く。基盤の価格管理も同時に着手し、次の戦略投資へ滑らかに繋ぐ。

# 8. 主要モジュールの要点

## 8.1 価格管理（加盟店別プライシング）

商品の価格を加盟店ごとに変更でき、本部は全店の価格を横断で閲覧できる。価格は2層で持つ：本部が標準価格（参考価格）を共有し、各加盟店が自店価格を上書き、公開サイトは自店価格（未設定なら標準価格）を表示する。本部は全店価格ビュー・監査ログ・（任意の）承認フローで統制する。

**法務上の留意：**フランチャイズで本部が販売価格を強制的に拘束すると独占禁止法上の「再販売価格の拘束」に当たる懸念があるため、本部が持つのは標準・参考・推奨価格帯にとどめ、実販売価格は加盟店が決定する（本部は閲覧・モニタリングのみ）。具体的な可否は専門家確認を前提とする。

## 8.2 問い合わせ流入分析 ＋ Meta広告連携

公開サイトにfirst-partyの軽量トラッキングを置き、流入元（UTM・参照元・ランディングページ等）を保持して問い合わせ（住宅では来場予約・資料請求）に紐づけ、集計する。Meta広告は配信URLに広告IDを動的付与し、Marketing APIで広告クリエイティブ（画像・見出し・本文/キャプション）と実績（費用・クリック率）を取得。これにより『どのバナー・どのコピーが予約を生み、CPAはいくらか』を、加盟店別・商品ライン別に分析でき、戦略に活かせる。これは加盟店への販促支援（本部の付加価値）にも直結する。

# 9. セキュリティ・プライバシー設計（見直し）

## 9.1 基本方針

本プラットフォームは、多数の加盟店の見込み客の個人情報（氏名・連絡先・問い合わせ内容、場合により住所や資金計画の入力値）を1つの基盤で預かる。したがって「最小権限」「データ最小化」「分離」「監査可能性」「同意」を設計原則とし、セキュリティとプライバシーを後付けではなく前提として組み込む。

## 9.2 マルチテナントのデータ分離（最重要）

最大のリスクは、ある加盟店が他店の見込み客・顧客データを閲覧できてしまうテナント越境である。UIだけでなくアクセス制御層でテナント境界を強制し、全クエリにテナント条件を必須化する。データベースの行レベルセキュリティ（RLS）を多層防御として併用し、テナント分離の自動テスト（他店IDを差し替えて取得できないか＝IDOR検証）を継続的に実施する。

## 9.3 個人情報保護（APPI対応）

- 利用目的の明示と同意取得（プライバシーポリシー、Cookie/トラッキング同意。同意前は計測しない）。

- データ最小化（資金計画シミュレーター等で年収などの機微情報は極力サーバーに保存しない）。

- 保持期間と削除、開示・訂正・利用停止請求への対応フロー。

- 委託先（運営・外部API・クラウド）の管理、本部・加盟店間のデータ取扱いの整理（委託／共同利用の明確化）。

- 漏えい時の対応体制（個人情報保護委員会への報告・本人通知を含む）。

## 9.4 認証・権限・本部アクセスの統制

- 加盟店ユーザーの認証強化（強パスワード、本部管理者は二要素認証必須）。招待トークンは有効期限・単回使用。

- 最小権限のロール設計（本部管理者／加盟店オーナー／加盟店スタッフ）。各ユーザーは自店スコープに限定。

- 本部の強い横断権限は監査ログ対象とし、個別個人情報の閲覧範囲を制限。リード所有権（5.4）を技術的にも担保する。

## 9.5 外部連携・トラッキングの安全性

- Meta広告・LINE・決済（Stripe）等のトークン/シークレットはサーバー側で暗号化保管し、スコープ最小化・ローテーション。クライアントに鍵を露出しない。

- OAuthの安全な実装、Webhookの署名検証、外部画像取得時のSSRF対策。

- 同意管理（CMP）と連動し、未同意時はトラッキングを行わない。IPからの地域推定は粗い粒度に留める。

## 9.6 アプリケーション脆弱性・インフラ・運用

- OWASP Top 10対策：入力のサニタイズ（XSS／リッチテキスト）、パラメータ化（SQLi）、CSRF、認可バイパス（IDOR）対策。

- ファイルアップロードは画像限定・検証・署名付きURL配信、メディアはテナント別アクセス制御。

- 登録・問い合わせのスパム/bot対策（reCAPTCHA＋レート制限）。

- 通信のTLS・保存時暗号化、秘密情報管理（Secrets Manager）、依存関係の脆弱性管理、バックアップ・復旧、ログ監視、インシデント対応計画、定期的な脆弱性診断。

- 可用性：1基盤で全加盟店を支えるため、冗長化・バックアップ・SLAを設計（1箇所の障害が全店に波及しないように）。

## 9.7 セキュリティ 最優先対応

| **領域** | **主なリスク** | **対策** | **優先度** |
| --- | --- | --- | --- |
| テナント分離 | 他店の見込み客・顧客データの越境閲覧 | アクセス制御層で強制＋RLS＋分離テスト（IDOR検証） | 最高 |
| 個人情報(APPI) | 同意なき取得・漏えい・目的外利用 | 同意管理・最小化・保持/削除・委託管理・報告体制 | 最高 |
| 本部の越権 | 強い横断権限の濫用・顧客引き抜き不信 | リード所有権の明確化・閲覧制限・監査ログ | 高 |
| 秘密情報 | API鍵/トークンの漏えい | サーバー側暗号化保管・最小スコープ・ローテーション | 高 |
| スパム/不正登録 | bot登録・フォーム悪用 | reCAPTCHA＋レート制限＋メール確認 | 中 |
| 可用性 | 障害の全店波及 | 冗長化・バックアップ・SLA・監視 | 中 |

# 10. 成功の定義（KPI）と検証計画

「本当に喜ばれているか」を感覚でなく数値で確認するため、以下を継続測定する。

| **指標** | **何を見るか** | **ねらい** |
| --- | --- | --- |
| 加盟店の利用率 | 実際にログイン・更新している加盟店の割合 | 使われている＝価値の前提 |
| 来場予約・資料請求数 | サイト経由のリード件数（店別・全国） | 受注の入口の増加 |
| リード→来場 CVR | 問い合わせから来場・相談への転換率 | 導線の質 |
| CPA | 1件あたりの広告獲得コスト | 販促ROIの改善 |
| 受注貢献 | サイト起点の商談・成約 | 最終成果 |
| 加盟店満足度(NPS)・継続率 | 推奨度・解約/離脱率 | “喜ばれているか”の直接指標 |

**検証計画：**少数のパイロット加盟店で先行導入し、上記KPIと現場の声で「本当に喜ばれるか」を実地検証してから全国展開する。影響度・実装負荷の見積りも、PoCの結果で再評価する。

# 11. 体制とロール

- **本部（運営・platform-admin）：**商品・ブランドメディア・標準価格の管理、全店の集計/ベンチマーク閲覧、伴走支援（素材・研修・広告支援）、セキュリティ統制。

- **加盟店オーナー：**自店サイトの編集、価格設定、メンバー招待、自店の見込み客・成果の管理。

- **加盟店スタッフ：**施工事例・お知らせ・予約対応などの日常運用（権限は自店スコープ）。

# 12. リスクと対策

| **区分** | **リスク** | **対策** |
| --- | --- | --- |
| 採用 | 多忙・非デジタルで使われない | 本部が初期設定/中身を用意、モバイル前提、伴走支援、シンプル設計 |

| 法務 | 価格拘束・個人情報・広告表示 | 標準価格に留める、APPI対応、表示順守、専門家確認 |
| 技術 | テナント越境・障害の全店波及 | 分離強制＋テスト、冗長化・バックアップ・監視 |

# 13. 実装ロードマップ

- **フェーズ0（基盤）：**モジュール基盤、予約・問い合わせの受け皿、価格管理、テナント分離とセキュリティの土台。

- **フェーズ1（クイックウィン＋核）：**施工事例強化、販促素材ライブラリ、“好き”診断、資料請求デジタル化、来場予約＋簡易CRM。少数加盟店でパイロット。

- **フェーズ2（戦略投資）：**価格・資金シミュレーター、広告ROI分析（Meta連携）、LINE連携、成果可視化＋全国ベンチマーク。

- **フェーズ3（深化）：**オンライン内覧、AIチャット相談、オーナーコミュニティ＋紹介、ローカルSEO/GBP（負荷次第で前倒し）。

基盤（価格管理・予約/CRM・セキュリティ）を先に薄く整えると、上位機能は“載せるだけ”になり、安全に拡張できる。
