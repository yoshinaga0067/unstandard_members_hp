このコマンドが呼ばれたら、以下を **この順序で** 実行してください。途中で問題があれば日本語でユーザーに伝えてください。

## ステップ0：リポジトリの確認（最初に必ず行う）

### 0.1 Git 初期化チェック

ルートに `.git/` ディレクトリが存在しない場合（ZIP ダウンロード等で取得されたケース）：
- `git init -b main` を実行
- ユーザーに一言：「ローカル用の Git を初期化しました。」

### 0.2 フェーズ判定

`.claude/phase3.lock` が存在するか確認：
- 存在しない → **フェーズ1**
- 存在する → **フェーズ3**

### 0.3 リモートの確認

`git remote get-url origin` の結果で分岐する。

**ケースA：リモートが設定されていない**

- **フェーズ1の場合** → そのまま続行する。一言だけ伝える：
  ```
  💡 GitHub にはまだ紐付けていません。ローカルで自由に作業を進められます。
     設定したくなったら「GitHub に紐付けて」と教えてください。
     ※ /publish のときに必要になります（公開だけしたい場合は Vercel への直接デプロイも可能です）
  ```

- **フェーズ3の場合** → 中断する。エンジニアに相談するよう案内：
  ```
  ⚠️ GitHub のリモートが設定されていません。
     フェーズ3 ではエンジニアが用意したリモートが必要です。
     エンジニアに相談してください。
  ```

**ケースB：リモートURLに `claude-md-template` が含まれている**

テンプレートのリモートを指したままなので、ユーザーに選択肢を提示：
```
⚠️ このフォルダはテンプレートのリモートを指したままです。
   どちらにしますか？

   A. 今すぐご自身の GitHub リポジトリを作って紐付ける
   B. テンプレートのリモートを外して、ローカルだけで進める（後で設定できます）
```

- **A を選んだ場合**：
  ```
  GitHub の手順：
  1. github.com にログインする
  2. 右上の「+」→「New repository」
  3. リポジトリ名を入力して「Create repository」
  4. 作成後の URL（例：https://github.com/yourname/projectname）を教えてください
  ```
  URL を受け取ったら `git remote set-url origin <URL>` で置き換える。

- **B を選んだ場合**：
  - `git remote remove origin` でテンプレートのリモートを外す
  - 「テンプレートのリモートを外しました。ローカルだけで進めます。」と伝える
  - 続行（以降はケースAのフェーズ1の流れと同じ）

**ケースC：別のリポジトリを指している**

問題なし。次のステップへ進む。

## GitHub を後から紐付ける場合

ユーザーが「GitHub に紐付けて」「GitHub を設定して」等と言った場合の手順：

1. リモートが既にあるか `git remote get-url origin` で確認
   - 既に別の URL が設定されていれば「すでに紐付け済みです」と伝える
2. ユーザーに URL を聞く：
   ```
   GitHub のリポジトリ URL を教えてください。
   まだ作っていない場合：github.com/new で新しく作成できます。
   ```
3. URL を受け取ったら：
   - `.git/` が無ければ `git init -b main`
   - `git remote add origin <URL>`（既に origin がある場合は `git remote set-url origin <URL>`）
4. 一言伝える：「紐付けました。次に `/publish` すると GitHub にもアップロードされます。」

## ステップ0.5：新規プロジェクトのブートストラップ

以下の **いずれか** が当てはまれば「新規プロジェクト」と判断する：

- ルートに `package.json` が **存在しない**
- `PROJECT-OVERVIEW.md` に `[プロジェクト名をここに入力]` という文字列が **残っている**

両方とも当てはまらなければ、このステップはスキップしてステップ1へ進む。

### 新規プロジェクトの場合の手順

順番に質問する（日本語、フレンドリーに）：

**質問1：デザインのテーマ**
```
デザインのテーマを選んでください：

1️⃣  HARMONY ... 自然素材・温かみ・フォーマル（親会社ブランド）
2️⃣  UNSTANDARD ... カラフル・ライフスタイル・カジュアル（若年層向け）
3️⃣  カスタム ... このプロジェクト独自のデザイン
```

詳細は `docs/DESIGN.md` を参照すること。

**カスタムを選んだ場合の追加質問**：

質問A：「参考になるウェブサイトのリンクはありますか？」
- ある → URL を受け取って WebFetch で読む。色・フォント・トーンを `docs/DESIGN.md` の末尾に「プロジェクト固有デザイン」セクションとして追記する。
- ない → 次へ

質問B：「デザインガイド（`design.md` など）はお持ちですか？」
- ある → ファイルのパスや内容を受け取って `docs/DESIGN.md` に取り込む
- ない → `docs/DESIGN.md` の末尾に以下の TODO ブロックを追記：
  ```
  ## TODO（カスタムテーマ）
  - [ ] 主要カラーを決める
  - [ ] フォントを決める
  - [ ] 参考サイトを追加する
  ```

**質問2：プロジェクト名**
- 「このプロジェクトの名前は？」

**質問3：認証・データベース**
- 「ユーザーログインやデータベースは必要ですか？」
- はい → Supabase のセットアップを後で案内（CLAUDE.md の Supabase ガイドに従う）
- いいえ → そのまま進む

### ブートストラップの実行

質問の回答を受けて以下を実行：

1. **Next.js のセットアップ**：
   ```
   npx create-next-app@latest . --typescript --tailwind --app --no-src-dir --no-import-alias
   ```
   既に部分的にファイルがある場合は確認してから上書き。

2. **テーマトークンの適用**（hex 値は `docs/DESIGN.md` から取得）：
   - **HARMONY** → `tailwind.config.ts` に以下を追加：
     - `harmonyAccent: '#da2308'`（赤系オレンジ）
     - `harmonyAccentLight: '#e28174'`
     - `harmonyText: '#333333'`、`harmonyTextMuted: '#555555'`
     - `harmonyBorder: '#b3b3b3'`、`harmonyBorderLight: '#dcdcdc'`
     - `app/globals.css` で Noto Sans JP をインポート
   - **UNSTANDARD** → `tailwind.config.ts` に以下を追加：
     - `unstandardAccent: '#e9d45a'`（マスタード）
     - `unstandardAccentLight: '#f6dc30'`
     - レインボーパレット（`rainbowRed: '#ed1c24'` 等）も `docs/DESIGN.md` 参照
     - Noto Sans JP をインポート
   - **カスタム** → `create-next-app` のデフォルトのまま。`docs/DESIGN.md` の TODO に従って後で調整。

3. **PROJECT-OVERVIEW.md の初期化**：
   - 一番上に「Design Theme」行を追加し、選んだテーマを記録（例：`HARMONY`）
   - 「Summary」にプロジェクト名と簡単な説明を入れる
   - **このテーマは固定**。以降のセッションでは自動で適用される。変更したい場合は手動で編集する。

4. **コミット**：
   - `git add -A`
   - `git commit -m "プロジェクトを初期化（テーマ：<選んだテーマ>）"`

ブートストラップが終わったら、ステップ1へ進む。

## ステップ1以降：通常の起動フロー

1. 現在のブランチを確認（`git branch --show-current`）

2. **未保存の変更を確認**：`git status --short` を実行する
   - 変更がある場合 → `git stash` で一時退避してからブランチを切り替える。切り替え後に `git stash pop` で戻す。ユーザーには「作業中のファイルを一時保存しました」と日本語で伝える。
   - 変更がない場合 → そのまま次へ

3. `develop` ブランチが存在しない場合は `git checkout -b develop` で作成。存在する場合は `git checkout develop`

4. リモートが設定されている場合のみ `git pull origin develop` で最新版を取得
   - リモート未設定（フェーズ1のローカル作業）の場合はスキップ
5. `CLAUDE.md` を読んでプロジェクトのルールを確認
6. `PROJECT-OVERVIEW.md` が存在すれば読んで、プロジェクトの概要を把握
7. プロジェクト直下のファイル構造を簡単に把握（`ls` 程度でOK）
8. **日本語で** 以下をユーザーに伝える：
   - 今 develop ブランチにいること
   - プロジェクトが何のためのものか（PROJECT-OVERVIEW.md から）
   - すでに作られている主な機能・ページ
   - 今日これから何をしたいか質問する

## 大切なこと

- 技術的な用語はなるべく避けてください（「ブランチ」程度はOK）
- 「準備できました。今日は何を作りますか？」のように、フレンドリーに締めくくってください
- ファイルを編集する必要はまだありません。状況把握だけです
